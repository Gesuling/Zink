# ZINK project status

Snapshot of the current source; update alongside behavior changes. See AGENTS.md for architecture and implementation details.

## Completed features

- Compose app shell with Home, Icons, Wallpapers, Apply, and Requests tabs plus full-screen Settings. Settings title/subtitle remain fixed over independently scrolling sections; the fixed glass bottom navigation stays available while Settings is open. Settings and Apply scroll areas leave space for system bars and bottom navigation.
- 84-entry bundled icon catalog with search, category filtering, details, and package-name copy.
- Launcher icon-pack XML/resources and manifest discovery hooks. Settings accurately displays the static 0.74 unthemed-icon fallback scale; it is not a dynamic masking toggle.
- 43 bundled wallpapers with All Wallpapers/Favourites filtering, immediate saved-favorite updates, a no-favourites empty state, preview transforms, download, and Home/Lock/Both application. Download quality persists with 4K Original as the default; FHD 1080p downsizes actual JPEG output within 1920×1080 landscape / 1080×1920 portrait bounds.
- Apply discovers HOME-capable apps dynamically with PackageManager ACTION_MAIN/CATEGORY_HOME queries and identifies the default only when the resolved activity matches a concrete candidate. Installed HOME apps, the current default, and DIRECT/MANUAL/ALTERNATIVE compatibility remain separate. Nova is Manual Setup Required: its undocumented APPLY_ICON_THEME action prompted for confirmation but did not complete application in the user's test; ZINK cannot observe that action's outcome. The guide now instructs Open Nova Settings → Look & Feel → Icon Style → Icon Theme → ZINK and offers OPEN NOVA LAUNCHER when installed. Action remains Direct Apply (user-confirmed working on Xiaomi); Lawnchair and Nothing are Manual Setup; Xiaomi System Launcher is Alternative Required. Direct-apply feedback reports only that a request was sent, not that the pack applied. Unknown HOME apps appear as installed but unverified alternatives; setup fallback activities are excluded and resource overlays without HOME activities are not surfaced. Lawnchair includes its current official Play package app.lawnchair.play plus GitHub/nightly/legacy variants. Detection refreshes when Apply composes and when ZINK resumes. PackageManager checks on Xiaomi model 23129RAA4G confirmed the current default `com.miui.home/.launcher.Launcher`, installed Nova/Action/Lawnchair (`app.lawnchair.play`), Nova's apply action resolving to `.IconThemePrompt`, and its normal launcher activity `.NovaShortcutHandler`. ZINK's updated Apply UI could not be verified because the debug APK installation was canceled by the device/user. The fixed Apply header/default card and scrolling launcher list remain in place. Launcher detail Open actions now verify the installed package, prefer its own MAIN/LAUNCHER entry point, and fall back only to that package's declared HOME activity (covering Xiaomi's HOME-only com.miui.home). They never substitute the current default launcher for another requested package. If no route can be started or Android denies it, the sheet displays an explanation and offers Android's default-app settings, with manual navigation guidance if unavailable. Directory cards remain content-sized with long names/status wrapping; the main list remains the sole launcher-directory scroll container.
- Requests screen with unthemed app discovery, themed catalog and manual-entry modes; unthemed apps begin unselected and require explicit user selection. Selected catalog requests include app names and package names in the email. The themed-app mode has a selected-count submit button, and failed email launch copies the request to the clipboard when available.
- Persisted Pure AMOLED Black, wallpaper download quality, favourite wallpaper IDs, Home Header Artwork selection, and transient screen states. Screen state managers (`RequestsSelectionManager`, `ApplyStateManager`, `IconsStateManager`, `WallpapersStateManager`) persist search queries, category/filter chips, request checkboxes (unthemed packages and themed app IDs), mode tabs, and manual request form inputs across tab switching, Activity recreation, and process death via SharedPreferences. Temporary dialogs and modal sheets (e.g. launcher details, icon dialogs, wallpaper preview) are intentionally transient.
- Standardized page headers across Settings, Apply, Requests, Icons, and Wallpapers using shared `ZinkPageHeader` and `ZinkToolbarHeader` components with consistent top spacing, title positioning (`24.sp`, `FontWeight.Light`, `letterSpacing = 4.sp`), and subtitle placement. Aligned the Home Settings gear and Settings Back button precisely on the same horizontal toolbar line with matching size, padding, and touch target.
- Interactive App Version release changelog bottom sheet in Settings > About > App Version displaying current version (v0.1.2 - 22 November 2026 planned release) and previous release history (v0.1.1 - 21 November 2026 published) with expandable version sections, structured metadata (`LATEST_PUBLISHED_VERSION`), and automatic publication status distinction. Polished release card layout with robust vertical spacing (14dp) between the version/current badge header and the planned release / release date text to prevent any collision across font scales and screen widths.
- Settings Clear Icon Cache functionality with in-memory bitmap cache eviction and cache directory cleanup, backed by `formatBytes` formatting helper and unit tests (`CacheManagerTest`).
- Granular confidence labeling in Apply: replaced the coarse and uniform `VERIFIED` count with a dynamic confidence breakdown in the list header (`TOTAL` count and color-coded confidence badges for `OFFICIAL`, `COMMUNITY`, and `UNVERIFIED`) matching `ConfidenceLevel`, and added individual confidence labels (`Official`, `Community`, `Unverified`) to each directory card (`confidenceLabel · availabilityLabel`).
- Physical device verification on Xiaomi Redmi Note 13 4G (model 23129RAA4G, Android 15 / HyperOS V816, 1080×2400): installed latest debug APK, launched app into Apply screen via target tab extra, inspected live Compose hierarchy and screen rendering. Confirmed:
  - Default launcher detection accurately identified `com.miui.home` as "System launcher" (Alternative Required).
  - Directory section header displays "15 TOTAL" with accurate color-coded confidence badges: "11 OFFICIAL", "1 COMMUNITY", "3 UNVERIFIED".
  - Cards show accurate labels and icons: Xiaomi HyperOS System Launcher shows `DEFAULT` tag, `Alternative Required` badge, and `Unverified · Installed`; Action Launcher shows `1-Tap Direct Apply`, `Community · Installed`, and `APPLY` button.
  - Logcat confirmed clean startup without crashes, exceptions, or routing errors, with live icon extraction for `com.miui.home`, `com.teslacoilsw.launcher`, `com.actionlauncher.playstore`, and `app.lawnchair.play`.
  - Tested launcher OPEN routing: Xiaomi HOME-only resolution (`com.miui.home/.launcher.Launcher`) successfully brought to front; standard launcher entry points for Nova (`.NovaShortcutHandler`), Action (`com.actionlauncher.ActionLauncherActivity`), and Lawnchair (`app.lawnchair.LawnchairLauncher`) verified and launched cleanly.
  - Default-app settings intent (`android.settings.MANAGE_DEFAULT_APPS_SETTINGS`) confirmed working on-device, opening system Default apps page with "Home app · System launcher".

## Incomplete work

- Launcher compatibility records/guides need device/version revalidation; manifest discovery filters do not prove compatibility. Unit tests cover HOME candidate matching, package-scoped Open route selection including HOME-only fallback and unavailable cases, Nova's manual method, Action's preserved direct action, confidence breakdowns, search/filtering, transient state persistence/restoration, and request-only Toast wording. Physical device verification confirmed Xiaomi HOME resolution, Nova, Action, Lawnchair open routes, and default-app settings on model 23129RAA4G. Note: direct `adb shell input` touch injection is restricted by HyperOS security settings unless USB debugging (Security settings) is enabled with Xiaomi account/SIM; automated instrumented test APK installation is blocked by HyperOS interactive prompt (`INSTALL_FAILED_USER_RESTRICTED`). 59 unit tests cover all routing, breakdown, filtering, state persistence, presentation, and changelog version formatting logic with 100% pass rate.
- Icon-pack XML is duplicated in assets and res/xml and needs parity when updated. The static 0.74 fallback scale only works in launchers that implement generated fallback rules; ZINK cannot toggle it at runtime. Kvaesitso documents fallback scale support; current Lawnchair docs say generated fallbacks are not implemented. Other launchers should be checked by version.
- Automated coverage remains limited: wallpaper dimensions, favorite ID/header artwork fallback rules, cache formatting, launcher confidence breakdown, search/filter partitioning, and launcher open routing have unit tests; saved quality, Android bitmap decoding, SharedPreferences persistence/restoration, stale favorite/header values, and packaged Lawnchair/Kvaesitso icon decoding have instrumentation tests. Most other feature flows remain uncovered.
- No backend for icon requests or remote icon/wallpaper catalog exists.
